智能财务分析 Agent · 知识点笔记

Python / FastAPI / LLM / Function Calling / RAG —— 项目逐行拆解 + 面试自检 + 诚实度对照
一句话定位：给一个财务问题，Agent 自己决定「查库 → 算指标 → 检索准则 → 跑脚本」的步骤组合，最后输出带依据的结构化报告。核心是 LLM 决定做什么，Python 负责真的去做，结果回填给 LLM 继续推理。

四、核心知识点逐段拆解

1. Function Calling 主循环 —— loop.py

这是整个 Agent 的心脏。原理：把「工具定义」发给模型，模型不只回文字，还会回tool_calls（"我想调 query_db，参数是…"）。Python 执行后把结果回填，再问模型下一步。

# loop.py 核心逻辑（简化）
for _ in range(MAX_ITERS):              # 最多循环 10 次，防死循环
    msg = _chat(messages)              # 调 DeepSeek，带 tools=TOOLS
    tool_calls = msg.get("tool_calls")
    if not tool_calls:               # 模型不再调工具 = 想好了，结束
        return {"answer": msg["content"], ...}
    for tc in tool_calls:
        fn   = tc["function"]["name"]
        args = json.loads(tc["function"]["arguments"])
        result = dispatch(fn, args)     # 真去执行工具
        trace.append({...})             # 记日志（可观测）
        messages.append({"role":"tool", "tool_call_id":tc["id"], "content":json.dumps(result)})
面试问：为什么要把结果回填成 tool 消息？
答：模型是无状态的，每次请求只看到 messages。不回填结果，模型就不知道查询返回了什么，无法基于真实数据继续推理。
面试问：MAX_ITERS 干嘛的？
答：防止模型陷入"一直调工具不停"的死循环，10 次封顶，超了就返回"未收敛"。
面试问：temperature 设多少、为什么？
答：0.2，低温度让工具调用更稳定、数字不胡编。

2. 工具定义与分发 —— tools/__init__.py

工具要用 JSON Schema 描述给模型，模型才知道"有哪些工具、每个工具要什么参数"。

# TOOLS：OpenAI function-calling 格式，一项一个工具
{
  "type": "function",
  "function": {
    "name": "calc_financial_model",
    "description": "计算财务模型/指标，如毛利率、WACC、DCF、IRR、预期信用损失",
    "parameters": {"type":"object", "properties":{
        "model_name": {"type":"string"},
        "params":    {"type":"object"}
      }, "required":["model_name","params"]}
  }
}

# dispatch：按名字把调用路由到真实 Python 函数
def dispatch(name, args):
    if name == "query_db":            return {"rows": db.query(args["sql"])}
    if name == "calc_financial_model": return _handle_calc(args["model_name"], args.get("params",{}))
    if name == "rag_search":         return {"results": RAG.search(args["query"])}
    if name == "run_python":         return run_code(args["code"])
面试问：description 为什么重要？
答：模型全靠 description 决定"什么时候该用哪个工具"。描述写不清楚，模型就会乱调。

3. 只读 SQL —— db.py

让 LLM 写 SQL 有风险（可能写 DROP/UPDATE）。这里在入口强制只读。

def query(sql, limit=50):
    s = sql.strip().lower()
    if not (s.startswith("select") or s.startswith("with") or s.startswith("pragma")):
        raise ValueError("仅允许只读查询（SELECT/WITH）")   # 非 SELECT 直接拒绝
    ...
面试问：怎么防 Agent 误改数据？
答：SQL 必须以 SELECT / WITH 开头才放行，白名单拦截，其余抛异常。这是"只读代理"。
面试问：limit 干嘛？
答：默认 LIMIT 50，防止一次把整表拉爆上下文。

4. 财务模型 —— financial_models.py

项目里"10+ 模型"分三类。全部纯 Python 公式，可离线验证、可单测。

类别模型公式（要能背）
比率类gross_margin 毛利率(收入 − 成本) / 收入
比率类net_margin 净利率净利润 / 收入
比率类current_ratio 流动比率流动资产 / 流动负债
比率类quick_ratio 速动比率(流动资产 − 存货) / 流动负债
比率类debt_to_equity 产权比率总负债 / 权益
比率类roe / roa净利/权益、净利/总资产
比率类asset_turnover 总资产周转收入 / 总资产
比率类inventory_turnover 存货周转营业成本 / 存货
估值类waccE/(E+D)·Re + D/(E+D)·Rd·(1−T)
估值类dcf 企业价值Σ FCF/(1+r)^t + 终值(Gordon)
估值类irr 内部收益率使 NPV=0 的贴现率，牛顿迭代求根
信用类expected_loss ECLPD × LGD × EAD
# ECL：预期信用损失，IFRS9 减值核心
def expected_loss(pd, lgd, ead):
    return pd * lgd * ead          # 违约概率 × 违约损失率 × 风险敞口

# IRR：牛顿迭代法求 NPV=0 的贴现率
def irr(cashflows, guess=0.1):
    r = guess
    for _ in range(100):
        v  = _npv(r, cashflows)         # 当前 NPV
        dv = derivative(r)              # NPV 对 r 的导数
        nxt = r - v / dv                # 牛顿步
        if abs(nxt - r) < 1e-9: return nxt
        r = nxt
面试问：IRR 用什么算法？
答：牛顿迭代（Newton-Raphson），用 NPV 的一阶导数迭代逼近使 NPV=0 的贴现率。
面试问：DCF 终值怎么算？
答：Gordon 永续增长模型，FCF_N×(1+g)/(r−g)，再折现回第 N 年。
面试问：ECL 三个参数含义？
答：PD 违约概率、LGD 违约损失率（1−回收率）、EAD 违约敞口。三者相乘得预期损失。

5. RAG 检索 —— rag.py

RAG = 检索增强生成：先从知识库检索相关片段，再交给模型生成，让答案有依据。

为什么用 TF-IDF 而不用向量库？因为 DeepSeek 不提供 embedding 接口，且 TF-IDF 轻量、可离线、可解释。

# 核心：把"问题"和"每篇文档"都转成 TF-IDF 向量，用余弦相似度排序
def search(self, query, k=3):
    qv = self._vec(query)               # 问题向量
    for i, tf in enumerate(self.tfs):
        dv = {w: c*self.idf.get(w,0) for w,c in tf.items()}  # 文档向量
        dot = sum(qv[w]*dv[w] for w in set(qv)&set(dv))
        scored.append((dot/(qnorm*dnorm), i))   # 余弦相似度
    scored.sort(key=lambda x:-x[0])          # 取 top-k
面试问：TF-IDF 是什么？
答：词频×逆文档频率。词出现越多越重要（TF），但太常见（如"的"）权重低（IDF）。用来把文本转成可比的向量。
面试问：中文怎么分词？
答：不用分词库，按 bigram（相邻两字）切，中文短语这样覆盖效果好，且零依赖。

6. 子进程执行 —— code_exec.py

让模型写一小段 Python 并真正运行（复现计算、格式化输出）。安全靠：子进程隔离 + 超时 + 输出截断。

import subprocess
p = subprocess.run([sys.executable, "-c", code],
                   capture_output=True, timeout=20)   # 20 秒超时
必须诚实说：这不是安全沙箱。代码注释和 README 都写明了"仅本地可信分析，非恶意代码场景"。面试如果问安全，直接说"子进程+超时，不是 Docker 级沙箱"。

五、要不要说明是 Claude Code 跑的？

结论：简历上不写"Claude Code 生成"。简历写的是项目和你做的事，工具不是内容。就像不会写"这个项目用 VSCode 打的"。

但有一条硬底线：

  • AI 辅助写代码是行业普遍、合法、甚至加分项（体现 AI Coding 能力）。面试官不问，不用主动声明；问到了，大方说"AI 协作，我主导设计、逐行验证"。
  • 绝对红线：简历写了什么，你就必须能讲清什么。问"IRR 什么算法"答不上，比"用了 AI"严重一百倍——那是简历造假感。
  • 所以你的任务不是背"Claude Code 帮我写了"，而是把下面这张表每一条都用自己的话讲出来。
