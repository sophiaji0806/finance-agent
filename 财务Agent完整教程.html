第 1 步：VS Code 是什么？CLI 是什么？

先分清三个东西

名字中文是什么长啥样
VS Code代码编辑器一个软件（有图标、可点击、有菜单）。用它打开文件、看代码、改代码。它不是 CLI，它是图形界面软件（GUI）。有菜单栏、左边文件列表、右边代码区
终端 / Terminal命令行窗口VS Code 里的一个小面板。在它里面打字、按回车，电脑就执行。黑底白字那个。黑框，一行行文字
CLI命令行界面一种交互方式的名字（Command Line Interface，用打字下命令），不是一个软件。终端就是 CLI 的一种。—
一句话：VS Code 是「编辑器 + 内置终端」的合体软件。编辑器用来看和改代码；终端用来运行代码。CLI = "打字下命令"这种方式的统称。所以：VS Code 本身不是 CLI，但它的终端是 CLI。

方式三：终端里用 curl 发请求（给面试演示"这是个 API 服务"用）

先起服务（同方式一 ①②），然后再开一个新终端（菜单「终端 → 新建终端」），敲：

curl -X POST http://localhost:8000/api/agent/analyze -H "Content-Type: application/json" -d "{\"query\":\"算一下深圳云科技2023毛利率\"}"
为什么要"再开一个新终端"？因为 uvicorn 会一直跑、占住那个窗口不停刷日志，同一个窗口没法再敲命令（敲进去会被服务器日志冲掉）。所以开两个窗口：一个跑服务器（一直停着），另一个发请求。
为什么你 uvicorn 会报错「无法将 uvicorn 项识别为...」？两种原因：① 你没先 cd 到项目目录（人还在 C:\Users\10147，那里没代码）；② Windows 下 uvicorn 这个短命令没进 PATH。万能写法是加 python -m 前缀：
python -m uvicorn app.main:app --reload ← 用这条更保险
"生成网页"到底是谁做的？服务器（uvicorn）负责把网页文件和接口发出去；网页本身是 web/index.html 这个文件，我提前写好了放在项目里。浏览器打开 http://localhost:8000 时，服务器把 index.html 内容发给浏览器，浏览器渲染成你能看的页面。这就是"网页"的完整链路。

第 5 步：术语词典（大白话）

Python —— 一种编程语言，也是你电脑上的程序。.py 文件是"用 Python 说的话"。免费开源。
包 / 库 / 依赖 —— 别人写好的打包代码，import 就能用。pip 负责下载。绝大多数免费开源。
import —— "把这个库拿过来用"。类比从工具箱拿扳手。
函数（function） —— 一段起好名字、可反复调用的代码。进去几个数，出来一个结果。
模块（module） —— 一个 .py 文件 = 一个模块。app.tools.db 指 app/tools/db.py。点号 = 文件夹层级。
API —— 程序之间"下单"的接口。类比餐厅菜单：点菜→做菜→上菜。
API key —— 调用收费 API 的"钥匙"。证明是你在用、钱记你账。要保密。
LLM（大语言模型） —— ChatGPT、DeepSeek 这类会聊天推理的 AI。在线服务，要联网要 key 要花钱。
DeepSeek —— 国产 LLM，有 API。本项目调它当"大脑"。
Function Calling（函数调用） —— 让 LLM 不只聊天、还能"喊你帮忙做事"。你告诉它有哪些工具，它回"我要调 X 工具、参数是…"，你执行完塞回给它。Agent 核心。
Agent（智能体） —— 能自己决定下一步做什么的程序。普通程序让算 A 算 A；Agent 自己判断先查库再算指标。
RAG（检索增强生成） —— 让模型先查资料再回答，不瞎编。流程：搜出相关文字→拼进提示词→照着回答。
TF-IDF —— 一个"文字找相似"的算法，几十年前经典方法，公开免费、不是公司产品。出现多的词重要(TF)，太常见词不重要(IDF)，相乘得权重，再比夹角(余弦相似度)。本项目用 Python 自己实现，不联网不花钱。
余弦相似度 —— 比较两个向量方向多接近，0~1，越接近 1 越像。
向量 / 向量化 —— 把文字变成一串数字。TF-IDF 是一种变法；更高级用 embedding 模型。
SQL —— 跟数据库说话的查询语言。SELECT * FROM companies = 把 companies 表所有列给我。
数据库（database） —— 专门存数据、能快速查询的东西。类比结构化账本。
SQLite —— 轻量数据库，整个库就是磁盘一个文件（本项目 data/finance.db）。不用装服务器，Python 自带，免费离线。
表（table） —— 数据库里一张表格。本项目两张：companies（公司）、financials（财务数字）。
FastAPI —— Python 库，快速搭"网站后端接口"。把函数变成网址。@app.get("/health") = 访问该网址触发函数。
uvicorn —— 服务器程序，真把 FastAPI 网站跑起来、接访问。
pytest —— 自动检查库。写"答案应该是 X"的断言，挨个跑看对不对。
Docker —— 把项目打包进"集装箱"，到任何电脑原样运行。
GitHub Actions / CI —— 改完代码推到 GitHub，自动云端跑测试。CI=持续集成。
JSON —— 存数据的文本格式，键值对。{"name":"深圳云科技"}。
JSON Schema —— 描述"JSON 长什么样"的规范。Function Calling 用它告诉模型工具要什么参数。
.env / 环境变量 —— 放敏感配置（如 key）的文件，不写死在代码里。
开源（open source） —— 代码公开、免费看免费用。Python/fastapi/SQLite/pytest/TF-IDF 都开源。
子进程（subprocess） —— 开独立小进程跑代码，出错不拖垮主程序。
超时（timeout） —— 限制最多等多久，超过强制停，防卡死。
temperature（温度） —— 控制模型回答随机性的参数。见 FAQ-6。

6.5 app/tools/financial_models.py —— 财务公式

def gross_margin(revenue, cogs):   # 毛利率
    if revenue == 0: return 0.0          # 除 0 保护
    return (revenue - cogs) / revenue # (收入-成本)/收入

def wacc(equity, debt, cost_equity, cost_debt, tax_rate):
    total = equity + debt
    we, wd = equity/total, debt/total
    return we*cost_equity + wd*cost_debt*(1-tax_rate)  # 加权平均资本成本

def expected_loss(pd, lgd, ead):  # ECL
    return pd * lgd * ead          # 违约概率×损失率×敞口

def irr(cashflows, guess=0.1):     # 内部收益率，牛顿迭代
    r = guess
    for _ in range(100):
        v = _npv(r, cashflows); dv = derivative(r)
        nxt = r - v/dv              # 牛顿步
        if abs(nxt-r) < 1e-9: return nxt
        r = nxt

第 7 步：财务公式 + 面试问答

类别模型公式（要能背）
比率类gross_margin 毛利率(收入−成本)/收入
比率类net_margin 净利率净利润/收入
比率类current_ratio 流动比率流动资产/流动负债
比率类quick_ratio 速动比率(流动资产−存货)/流动负债
比率类debt_to_equity 产权比率总负债/权益
比率类roe / roa净利/权益、净利/总资产
比率类asset_turnover 总资产周转收入/总资产
比率类inventory_turnover 存货周转营业成本/存货
估值类waccE/(E+D)·Re + D/(E+D)·Rd·(1−T)
估值类dcf 企业价值Σ FCF/(1+r)^t + 终值(Gordon)
估值类irr 内部收益率使 NPV=0 的贴现率，牛顿迭代求根
信用类expected_loss ECLPD × LGD × EAD
问：IRR 用什么算法？
答：牛顿迭代（Newton-Raphson），用 NPV 一阶导数迭代逼近使 NPV=0 的贴现率。
问：DCF 终值怎么算？
答：Gordon 永续增长模型 FCF_N×(1+g)/(r−g)，再折现回第 N 年。
问：ECL 三个参数含义？
答：PD 违约概率、LGD 违约损失率（1−回收率）、EAD 违约敞口，三者相乘得预期损失。

Q1：为什么 cd finance-agent 报"找不到路径 C:\Users\10147\finance-agent"？cp 是把 example 换成 key 吗？

看知识库：用 VS Code 编辑器直接打开 app/knowledge/corpus.json。里面是 JSON 数组，共 7 条，每条有 title + text。7 个标题：新收入准则五步法 / 时点确认vs时段确认 / IFRS9金融工具分类与减值 / 估值DCF·WACC·可比公司 / 信贷风险IRB与PD·LGD / 审计SOX·C-SOX内控 / 机器学习与NLP基础。

补充知识：打开 corpus.json，照格式加一条 {"title":"新标题","text":"新内容"}，保存，重启服务即可（rag.py 启动时读一次）。

Q3：uvicorn 报错？"生成网站"是谁做的？为什么再开新终端？
答：报错两种原因：① 没先 cd 到项目目录，人还在 C:\Users\10147，找不到 app 模块；② Windows 下 uvicorn 短命令没进 PATH。万能写法：python -m uvicorn app.main:app --reload。
网页是谁做的：网页文件 web/index.html（我提前写好的静态文件）+ uvicorn 负责把它发出去 + 后端接口 /api/agent/analyze 负责算答案。浏览器打开 http://localhost:8000 时，服务器把网页发给你，网页再用 JS 去调接口拿结果。这就是一个最小的全栈应用。
"再开新终端"因为 uvicorn 一直跑、占住窗口刷日志，同一窗口没法再敲命令。开两个窗口：一个跑服务器，一个发请求。
Q4：为什么最多 10 轮？什么情况超 10 轮？
答：对，就是防大模型一直要求调工具、永远不结束。正常问题 1~3 轮结束。超 10 轮可能：模型逻辑混乱、重复调同一工具、或问题太复杂它不停查不停算。10 是上限保险（保险丝），不是目标。设的地方：loop.py 里 MAX_ITERS，值来自 .env 的 AGENT_MAX_ITERS。超了就返回"未收敛"。
Q5：tool_calls = msg.get("tool_calls") 怎么理解？大模型回答自带 tool_calls 字段吗？提示词里会说明吗？
答：msg.get("tool_calls") = 从模型返回的 message 里取 tool_calls 字段，没有就返回 None（None = 模型不调工具，直接给最终答案）。
会自带：因为请求时传了 tools=TOOLS 参数（loop.py 的 _chat 里）。DeepSeek 看到工具列表后，如果觉得"这个问题需要查数据/算指标"，它的返回 message 里就会带 tool_calls 数组；不需要就不带。
提示词两个层面：① 工具的"说明书"通过请求的 tools 参数传给模型（不是写在 system prompt 文字里），模型读的是 tools 里的 JSON Schema；② system prompt 文字里也确实教了它"什么时候用哪个工具"（第 1~4 条）。
Q6：temperature 是什么？在哪设？设多少为什么？
答：temperature = 采样温度，控制模型回答的随机性。0 = 最确定（几乎每次一样），越高越随机、越"有创意"。财务分析要稳定、数字不能乱编，所以设低 0.2。
在哪设：loop.py 的 _chat 函数里，第 37 行：json={"model":MODEL, ..., "temperature": 0.2, ...}。
Q7：把 4 个工具的 Function Calling 定义逐字段讲清
答：先讲通用结构，每个字段含义：
"type":"function" —— 声明这是一个"函数型工具"（还有别的类型，这里只用 function）。
"function" —— 包住工具的具体描述。
"name" —— 工具名字，模型返回 tool_calls 时用这个名字点你。
"description" —— 这工具干嘛用。模型靠它决定"什么时候该用这个工具"，写不清楚模型就乱调。
"parameters" —— 参数说明，用 JSON Schema：type:object 表示参数是一组键值；properties 列出每个参数名和类型；required 列哪些参数必须给。
完整 4 个工具： 
# 工具1：查数据库
{"type":"function", "function":{
  "name":"query_db",
  "description":"对财务数据库执行只读 SQL 查询（SELECT/WITH）",
  "parameters":{"type":"object", "properties":{"sql":{"type":"string"}}, "required":["sql"]}
}}

# 工具2：算财务模型（你的截图这个）
{"type":"function", "function":{
  "name":"calc_financial_model",
  "description":"计算财务模型/指标，如毛利率、WACC、DCF、IRR、预期信用损失",
  "parameters":{"type":"object", "properties":{
      "model_name":{"type":"string"},   # 要算哪个模型，如 gross_margin
      "params":{"type":"object"}         # 模型要的数字，如 revenue/cogs
    }, "required":["model_name","params"]}
}}

# 工具3：RAG 检索
{"type":"function", "function":{
  "name":"rag_search",
  "description":"在会计准则/审计/估值知识库做语义检索（RAG）",
  "parameters":{"type":"object", "properties":{"query":{"type":"string"}}, "required":["query"]}
}}

# 工具4：跑 Python 脚本
{"type":"function", "function":{
  "name":"run_python",
  "description":"执行一小段 Python 财务运算脚本（复现计算/格式化输出）",
  "parameters":{"type":"object", "properties":{"code":{"type":"string"}}, "required":["code"]}
}}
模型"调用工具"时回的东西长这样（这就是 loop.py 里读的 tool_calls）：{"id":"...","function":{"name":"calc_financial_model","arguments":"{\"model_name\":\"gross_margin\",\"params\":{\"revenue\":1200,\"cogs\":700}}"}} —— name 是工具名，arguments 是 JSON 字符串（要 json.loads 转成 dict），id 用来对应回填。

最小可面清单（背这 8 句）：
① Agent = 模型决策 + Python 执行 + 结果回填，循环到不再调工具。
② Function Calling = 把工具 schema 发给模型，模型回 tool_calls。
③ 毛利率=(收入−成本)/收入；流动比率=流动资产/流动负债。
④ IRR 用牛顿迭代求 NPV=0；DCF=Σ折现+Gordon 终值；ECL=PD×LGD×EAD。
⑤ RAG 用 TF-IDF 因为 DeepSeek 没 embedding 接口，轻量可解释。
⑥ SQL 强制只读：非 SELECT/WITH 开头就拒绝。
⑦ 子进程跑代码，隔离+超时+截断，非安全沙箱。
⑧ tool_trace 记录每次工具调用的名字/参数/结果/耗时，做可观测。
